# Auraxis 毕业设计文档（正文骨架与素材）

> 本文件是论文正文的素材与骨架，各节标题对应论文章节。占位符 `【】` 处需按学校模板与个人表述补全。

## 一、选题背景与需求分析

### 1.1 背景

AI 编程助手已成为软件开发的重要工具，但主流产品以云端服务或 Web/CLI 形态为主。本项目选题为：**在桌面端构建一个功能完备、可本地控制权限与沙箱、具备多智能体与工具编排能力的 Agentic 编程助手**。

### 1.2 需求分析

- **功能需求**：对话问答；Agent 模式的任务规划、执行、工具调用、暂停恢复；63 个模型工具；多 Agent 调度与子代理分叉；持久会话与历史检索；集成终端。
- **安全需求**：权限三模式（ask/plan/afe）、权限 profile、原生进程沙箱、路径边界与 read-before-write 观测。
- **体验需求**：流式输出、工具/思考折叠行、消息时间轴导航、悬浮输入区、深/浅双主题。
- **非功能需求**：桌面端离线可用（除 LLM API 外）、可扩展（插件/SDK/ACP）、可测试（自动化测试与覆盖率门禁）。

## 二、系统总体设计

### 2.1 总体架构

```text
┌─────────────────────────── Electron Main ───────────────────────────┐
│ 窗口/安全(CSP) │ IPC 总线 │ 统一步进引擎 │ 工具执行管线 │ 权限/沙箱   │
│ Agent 调度器  │ 会话事件日志 │ 记忆/FTS │ 终端/SSH │ ACP/SDK/headless │
└───────────────────────────────┬────────────────────────────────────┘
                                │ contextBridge / IPC
┌───────────────────────────────▼────────────────────────────────────┐
│ React 18 + AntD + Zustand（消息/输入/工作台/设置/终端/时间轴）      │
└────────────────────────────────────────────────────────────────────┘
```

### 2.2 模块划分

| 层 | 模块 | 职责 |
|---|---|---|
| 主进程 | step-engine / query-engine / agent-loop | 统一 ReAct 步进、两条驱动 |
| 主进程 | tool-defs / tool-handlers / tool-runner | 工具定义、执行、批处理与并发 |
| 主进程 | permission-handlers / permission-profile / sandbox-runner | 权限与沙箱 |
| 主进程 | session-store / chat-log / session-log / fts | 事件日志、投影、检索 |
| 主进程 | code-mode / fork-runner / schedule-store / attachments | Code Mode、分叉、跟进、图片 |
| 渲染层 | components（chat/input/layout/agent/settings/tools…） | UI |
| 渲染层 | stores（17 个 Zustand Store） | 状态管理 |
| 包 | packages/auraxis-sdk / python/auraxis_sdk | TS / Python SDK |

### 2.3 关键数据流

```text
用户输入 → 驱动(聊天/Agent) → step-engine 步进
  → LLM 流式响应 → 工具批 → tool-runner（并发分批）
  → executeToolCall（profile→沙箱→审批→执行→观测）
  → 结果追加事件日志 → 停止策略评估 → 下一轮或结束
```

## 三、详细设计与关键流程

### 3.1 统一步进引擎

一个 step = 一次 LLM 请求（含重试）+ 一次工具批 + 历史追加 + 停止评估 + 上下文压缩。聊天与 Agent 共享该实现，差异通过策略钩子注入（onBeforeRequest / onToolSummary / reviewGate / interceptTool 等）。

### 3.2 工具执行管线（重点阐述）

权限 profile 硬边界 → 沙箱门（先于审批失败）→ 规则匹配 → 模式感知自动批准/对话框 → worktree 重定向 → 撤销备份 → 多 Agent 冲突锁 → 执行 → 观测登记。给出时序图与逐层职责表。

### 3.3 Code Mode

TypeScript 程序体在 worker 线程执行，`await tools.Name(args)` 经消息通道提交；主进程按“提交顺序启动、并发安全工具最多 8 路重叠、变异工具串行”调度，子调用回穿完整工具管线；硬超时/中止 terminate worker。给出调度器伪代码与并发正确性说明。

### 3.4 会话事件日志与 lineage

统一词表（user/assistant_chunk/thinking_chunk/tool/command/system/agent_status），聊天与 Agent 共用 append-only JSONL 存储；投影、回放、fork、检索、事件级 lineage（turn 划分 + toolCallId 家族）全部由日志派生。

### 3.5 原生沙箱

Windows restricted token + Job Object / AppContainer、Linux、macOS 四种后端；read / workspace-write / full 三档语义；降级与拒绝策略。

## 四、测试方案与测试结果

## 五、部署与运行手册

1. 环境：Node 22.12+（本项目在 Node 24 上验证），npm。
2. `npm install` → `npm run electron:dev` 开发；`npm run build` 产出 NSIS/DMG/AppImage 安装包。
3. 配置：复制 `.env.example` 为 `.env`，填 `DEEPSEEK_API_KEY`（或 OpenAI/Anthropic 兼容端点）。
4. 无头：`npm run cli -- --run "<任务>" --project <路径> --mode afe`。
5. SDK：TS（TCP JSON-RPC）、Python（`pip install ./python/auraxis_sdk`）。

## 六、本人工作边界与贡献
